# AI 问数转数据开发任务方案

## 1. 方案定位

当前系统已经具备 AI 问数、Skill 知识、报告模板、数据开发任务和 DolphinScheduler 调度执行能力。后续智能化重点不应停留在一次性问答，而是把业务人员的一次分析需求沉淀成可确认、可发布、可执行、可复用的数据开发资产。

核心定位：

```text
AI 负责生成分析方案，系统负责固化和稳定执行。
```

也可以概括为：

```text
系统驱动 AI，而不是 AI 驱动系统。
```

系统先提供数据源、资产、字段、Skill、权限、任务类型和执行链路，AI 在这些边界内生成 SQL、脚本、参数、结果结构和报告草稿。用户或开发人员确认后，系统把方案转换为数据开发任务。后续业务人员不需要反复和 AI 对话，只需要调整参数、点击执行、查看结果或生成报告。

## 2. 要解决的问题

### 2.1 当前 AI 问数的问题

AI 问数适合探索式分析，但不适合把常用业务分析长期依赖在每次对话上：

- 同一个问题多次提问，SQL 和解释可能不完全一致。
- 复杂口径需要反复补充上下文，业务人员使用成本高。
- 问答结果缺少任务化管理，难以调度、复用、审计和版本化。
- AI 生成结果如果不进入系统流程，无法形成稳定的数据资产。

### 2.2 当前数据开发的问题

数据开发链路稳定，但传统方式对业务人员不够友好：

- 业务人员知道要分析什么，但不一定知道库表、字段和 SQL。
- 开发人员需要反复理解业务问题，再手工写 SQL 或脚本。
- 常见分析任务从需求到执行链路较长。
- 报告生成和数据开发任务之间缺少自动衔接。

### 2.3 本方案的目标

本方案目标不是让 AI 直接替代数据开发，而是让 AI 生成“候选开发资产”，再由系统确认、发布和执行：

- 一次问数可以沉淀为一个分析方案。
- 一个分析方案可以转换为数据开发任务。
- 一个数据开发任务可以稳定执行并产出结果数据。
- 结果数据可以绑定报告模板，生成确定口径的报告。
- AI 参与生成、解释、优化和修正，系统负责权限、版本、执行、调度和审计。

## 3. 和现有能力的关系

### 3.1 AI 问数

现有 AI 问数负责自然语言理解、Skill 检索、SQL 生成、结果解释和报告数据生成。它仍然保留探索式问答能力。

本方案在 AI 问数之后增加“保存为分析方案”和“转换为开发任务”能力。普通问数不直接自动执行 SQL，也不绕过系统任务链路。

### 3.2 Skill 知识

Skill 继续作为 AI 理解业务和数据的基础：

- 元数据 Skill 提供库、表、字段、血缘和资产上下文。
- 质量探查 Skill 提供数据可信度和异常风险。
- 表级 Skill 提供字段含义、常用过滤条件和指标口径。
- 报告模板 Skill 提供报告结构、指标要求和分析规则。

AI 生成分析方案时必须引用相关 Skill，并记录引用来源，方便后续审核和追溯。

### 3.3 数据开发

当前数据开发复用 collector ETL 任务体系，通过 `type = 3` 区分，组件包括 SQL、存储过程、Shell、Python。

本方案不重建一套数据开发后台，而是把 AI 生成的分析方案转换为现有数据开发任务：

```text
分析方案
  -> 数据开发任务 type=3
  -> SQL / Shell / Python / 存储过程组件
  -> 发布
  -> 执行或调度
  -> 结果数据集
  -> 报告或导出
```

### 3.4 报告模式

报告模式继续负责按模板生成结构化报告。区别是：

- 探索阶段：AI 可以临时生成报告草稿。
- 固化阶段：报告绑定已确认的任务输出和报告模板。
- 执行阶段：系统先执行数据开发任务，再用确定结果生成报告。

## 4. 总体流程

```text
业务人员提问
    |
    v
AI 问数生成分析方案
    |
    v
展示 SQL / 脚本 / 参数 / 输出字段 / 图表建议 / 报告大纲
    |
    v
用户确认或开发人员修正
    |
    v
保存为分析方案
    |
    v
转换为数据开发任务
    |
    v
发布任务
    |
    v
点击执行或配置调度
    |
    v
生成结果数据集
    |
    v
查看结果 / 导出 / 生成报告
```

## 5. 核心对象设计

### 5.1 分析方案

分析方案是 AI 问数和数据开发之间的中间资产。它不是单纯聊天记录，也不是已经发布的任务。

建议包含：

| 字段 | 说明 |
| --- | --- |
| 方案名称 | 由用户命名或 AI 根据问题生成 |
| 业务问题 | 用户原始问题 |
| 分析目标 | AI 对问题的结构化理解 |
| 数据源 | 使用的数据源或数据库 |
| 引用 Skill | 本次分析引用的 Skill、版本和片段 |
| SQL 内容 | 查询 SQL 或待确认 SQL |
| 脚本内容 | Shell、Python 或存储过程内容，可为空 |
| 参数定义 | 时间、机构、产品、客户类型等可变参数 |
| 输出字段 | 结果列名称、类型、业务含义和展示顺序 |
| 结果类型 | 明细、汇总、趋势、排名、对比、报告数据 |
| 图表建议 | 折线图、柱状图、表格、指标卡等 |
| 报告模板 | 可选绑定报告模板 |
| 风险提示 | SQL 风险、质量风险、权限风险、口径待确认项 |
| 审核状态 | 草稿、待确认、已确认、已转任务、已废弃 |

### 5.2 任务转换记录

分析方案转换为数据开发任务时，应保存转换关系：

| 字段 | 说明 |
| --- | --- |
| 分析方案 ID | 来源方案 |
| 任务 ID | 生成的数据开发任务 |
| 任务类型 | SQL、Shell、Python、存储过程 |
| 转换人 | 操作用户 |
| 转换时间 | 操作时间 |
| 转换版本 | 使用的方案版本 |
| 转换结果 | 成功、失败、部分成功 |

这样后续可以从任务追溯到 AI 生成来源，也可以从方案查看已经生成过哪些任务。

### 5.3 结果数据集

任务执行后应把结果注册为结果数据集，而不是只停留在执行日志里。

建议包含：

| 字段 | 说明 |
| --- | --- |
| 数据集名称 | 结果数据名称 |
| 来源任务 | 数据开发任务 ID |
| 来源实例 | 本次执行实例 ID |
| 参数快照 | 本次执行使用的参数 |
| 结果字段 | 字段名称、类型、含义 |
| 数据存储 | 临时表、结果表、文件或缓存 |
| 数据有效期 | 临时结果清理策略 |
| 权限范围 | 谁可以查看、导出、生成报告 |

## 6. 功能设计

### 6.1 AI 问数页面增强

在现有问数结果基础上增加：

- 保存为分析方案。
- 查看引用 Skill。
- 查看生成 SQL 或脚本。
- 查看参数定义。
- 查看输出字段结构。
- 查看质量和权限风险。
- 发起方案确认。
- 转换为数据开发任务。

普通问数仍然可以直接返回答案、表格、图表或报告草稿；只有用户明确保存和确认后，才进入任务化流程。

### 6.2 分析方案管理

新增分析方案管理页面，用于沉淀 AI 生成的可复用分析能力。

核心操作：

- 新建方案。
- 编辑 SQL、脚本、参数、输出字段。
- 查看 AI 生成历史。
- 查看 Skill 引用来源。
- 方案版本管理。
- 方案审核确认。
- 转换为数据开发任务。
- 废弃方案。

方案管理面向业务分析人员、数据开发人员和管理员，不面向普通一次性查询。

### 6.3 转换为数据开发任务

本方案推荐优先把 AI 问数方案统一转换为 Python 开发任务，而不是让普通问数结果直接执行 SQL，也不是由 Java 服务在线代执行。

执行主体应是 DolphinScheduler 中的数据开发 Python 任务：

```text
AI 生成 SQL + 纯数据处理逻辑
  -> 系统包装标准 Python 文件
  -> 生成 type = 3 数据开发任务
  -> DolphinScheduler 执行 Python 任务
  -> Python 执行 SQL、处理数据、写入结果表
  -> 系统登记结果数据集
```

转换策略：

| 方案内容 | 数据开发组件 |
| --- | --- |
| 只读查询 SQL | 优先包装为 Python 开发 |
| SQL + 轻量数据处理 | 包装为 Python 开发 |
| 报告数据准备 | 包装为 Python 开发 |
| 存储过程调用 | 后续按需支持存储过程开发 |
| Shell 脚本 | 后续按需支持 Shell 开发 |

转换规则：

- 只允许转换通过安全检查的 SQL 或脚本。
- 默认生成 `type = 3` 的数据开发任务。
- 首期优先生成 Python 开发组件。
- 任务名称默认使用方案名称，可人工调整。
- 参数定义转换为任务参数。
- 输出字段转换为结果数据集字段。
- 引用 Skill、原始问题和风险提示写入任务备注或扩展配置。

### 6.4 标准 Python Runner

系统生成的 Python 文件应采用固定模板。AI 不直接生成完整可执行脚本，只生成受控片段：

1. 查询 SQL。
2. 参数定义。
3. 纯数据处理函数。
4. 输出字段说明。
5. 报告数据结构建议。

标准 Python 文件由系统包装，建议结构如下：

```python
SQL = """
select ...
"""

def transform(context, columns, rows):
    # AI 只允许生成这里的纯数据处理逻辑
    return {
        "columns": columns,
        "rows": rows,
        "summary": {}
    }

def main():
    # 系统模板负责：
    # 1. 读取任务参数
    # 2. 读取数据源连接配置
    # 3. 执行 SQL
    # 4. 调用 transform
    # 5. 创建或写入结果表
    # 6. 调用 DataMaster 接口登记结果数据集
    # 7. 输出执行摘要
    pass
```

其中 `main()`、数据库连接、结果表写入、结果登记等代码由系统模板生成，不由 AI 自由生成。

AI 生成的 `transform()` 只允许使用 Python 标准库完成纯数据处理：

- 字段重命名。
- 派生字段。
- 分组汇总。
- 排序。
- TopN。
- 占比。
- 同比和环比。
- 简单异常标记。
- 报告摘要所需指标结构。

禁止 AI 生成或使用：

- 第三方依赖安装。
- 自定义数据库连接代码。
- 文件系统任意读写。
- 网络请求。
- 系统命令。
- `eval`、`exec`、`__import__` 等动态执行能力。

数据库依赖由 DS Worker 的标准 Python 运行环境统一提供。任务不允许运行时 `pip install`。第一阶段可以只支持系统运行环境已预置驱动的数据源类型；后续再通过运行环境版本升级扩展数据库支持范围。

### 6.5 执行和调度

转换后的任务复用现有发布、执行、调度和日志能力：

- 手动点击执行。
- 配置调度周期。
- 查看任务实例。
- 查看执行日志。
- 查看输出结果。
- 失败后回到分析方案或任务编辑页修正。

AI 不直接负责调度执行，执行稳定性交给现有任务体系。

### 6.6 根据确定数据生成报告

报告生成应优先基于已确认任务输出，而不是每次重新让 AI 即兴生成。

推荐流程：

```text
选择已发布任务
  -> 执行任务
  -> 生成结果数据集
  -> 选择报告模板
  -> 填充模板
  -> AI 生成摘要、原因分析和建议
  -> 保存报告快照
```

报告中的指标、表格和图表来自确定数据；AI 主要负责摘要、解释、归因建议和文字润色。

## 7. 权限和安全边界

### 7.1 SQL 安全

- 问数阶段可以生成候选 SQL。
- 方案确认前不应自动执行高风险 SQL。
- 转换为任务前必须做 SQL 安全检查。
- 默认只允许 `SELECT` 查询。
- 涉及写入、删除、DDL、存储过程调用时必须走更严格的人工确认。
- 必须限制执行超时时间、最大返回行数和结果保存范围。

### 7.2 数据权限

AI 生成方案必须继承当前用户权限：

- 无权访问的数据源不能被引用。
- 无权访问的资产、表、字段不能出现在方案中。
- 敏感字段需要脱敏、隐藏或禁止使用。
- 结果数据集权限不能超过来源数据权限。

### 7.3 审核和版本

分析方案和数据开发任务都需要版本化：

- AI 原始回答要保存。
- 人工修改内容要保存。
- 每次转换任务要记录方案版本。
- 每次报告生成要记录任务实例和参数快照。
- 已发布任务不应被 AI 自动覆盖。

## 8. 系统智能性的体现

本方案中的智能性不是让 AI 每次直接给最终答案，而是让系统持续沉淀和复用分析能力：

- 第一次由 AI 生成初版方案。
- 第二次复用已确认方案。
- 第三次只调整参数执行任务。
- 常用方案沉淀为标准分析模板。
- 执行结果沉淀为结果数据集。
- 报告模板沉淀为可复用分析产品。

这样系统会常用常新，同时保持稳定。

## 9. 推荐落地阶段

### 阶段一：方案保存

- 在 AI 问数结果中增加“保存为分析方案”。
- 保存原始问题、生成 SQL、引用 Skill、参数、输出字段和风险提示。
- 增加分析方案列表和详情页。

### 阶段二：方案确认和版本

- 支持编辑 SQL、参数和输出字段。
- 支持方案版本。
- 支持确认、废弃、重新生成。
- 支持 SQL 安全检查和格式化。

### 阶段三：转换数据开发任务

- 支持把确认后的方案转换为 `type = 3` 数据开发任务。
- 首期优先支持标准 Python Runner，系统包装 Python 文件并生成 Python 开发任务。
- AI 只生成 SQL 和纯数据处理函数，不生成完整执行脚本。
- 后续按需支持存储过程和 Shell 等特殊组件。
- 保存方案和任务之间的映射关系。

### 阶段四：执行结果数据集

- 支持任务执行后注册结果数据集。
- 支持结果预览、导出和权限控制。
- 支持按参数快照查询历史结果。

### 阶段五：报告固化

- 支持结果数据集绑定报告模板。
- 支持根据确定结果生成报告。
- AI 只生成摘要、解释和建议，不改变指标数据。
- 保存报告快照和生成依据。

## 10. 不修改的边界

本方案不改变现有主流程：

- 不重建数据开发后台。
- 不替代现有 collector ETL 任务体系。
- 不改变 `type = 3` 数据开发任务标识。
- 不取消 AI 问数的探索式对话能力。
- 不让普通问数默认自动执行 SQL。
- 不由 Java 服务在线代执行 AI 问数 SQL。
- 不让 AI 自由生成完整 Python 脚本或自行安装依赖。
- 不让任务运行时 `pip install` 第三方包。
- 不让 AI 绕过数据源、资产、字段和菜单权限。
- 不让 AI 自动发布或覆盖已发布任务。
- 不把报告模板变成纯自然语言描述，仍以结构化模板为准。
