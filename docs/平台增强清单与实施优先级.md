# 平台增强清单与实施优先级

更新时间：2026-11-12。本文是整体评估与后续增强的统一台账，不把需求确认当成实现，不把代码修改当成运行验收。根README第1.1/1.2节记录产品原则并链接本文。

## 一、已确认原则及评估修正

1. 平台已有正常使用的功能体系，人工维护不是当然缺陷；提供丰富能力，但按项目规模和需要裁剪，优先把数据用起来。
2. **未配置资产/质量功能准入时可使用轻量路径；配置了就属于严格模式，必须执行，不可降级回退绕过。** 比如配置资产但只有元数据，API开放/调用和分析均不可使用该来源。
3. 质量准入有两种有效依据：检查达标；有权限的人确认指定范围数据可用。检查不达标可以人工通过，但保留原结果、确认人/原因/范围/时间。忽略个别错误不等于整表放行。资产准入与用户权限分别满足。
4. 空间定义规则、表/资产记录状态；库级批量须明确表集合，多表消费检查全部来源。发布/使用时检查当前准入，不要求每次使用重跑检查；时效规则按项目需要配置。
5. 前端提供流程和导航，后端必须检查已发布空间规则；流程配置草稿不影响现行规则，发布前说明存量影响，发布后不为旧调用静默回退。
6. ODS/DWD/DWS/ADS、业务分类、数据域/主题域及命名是人工治理约定，不是必经系统功能节点；不强制层层流转，不把ADS命名当全项目查询授权。
7. 数据开发是独立工具，不另加无关流程门禁；访问受控来源仍遵守权限，输出数据开放时服从已配置准入。质量批量修复复用开发，不另造清洗引擎。
8. 已有责任人不是缺失：元数据库/表/字段已有businessLeader/techLeader/responsibleDept，探查任务同步业务负责人/部门；质量任务有contactId/contact。优先贯通分派/通知，复核交接、可见性和展示，不重复建字段。
9. 标准/数据元审核优先级低；可信数据产品、完整MDM等按实际项目需要建设，不列为所有项目必须补齐的基础缺口。

### 核验依据

- 访问回退受 `TableGovernanceProperties.enabled/mode/fallbackToCatalog` 控制，`AssetsTableGovernanceApiServiceImpl` 存在回退及缺上下文放行路径。**不能简单认定回退本身错误**，也不能把当前global strict等同将来的空间严格准入；后续只在配置了功能流程的空间禁止回退，未配置保持兼容。
- `CatalogTableDO`等元数据模型的负责人/负责部门，以及 `CatalogTaskServiceImpl.updateResponsibleInfoForMetadata` 的同步链路，证明已有责任基础。先前“缺责任人”的概括修正为“现有责任信息与整改/通知尚需贯通”。
- 质量 `QualityTaskExecutorServiceImpl.updateErrorData` 在updateType=1时直接UPDATE物理表，再更新错误存储；`JdbcErrorDataStorage`支持修复前后值、备注和忽略。不是没有修复，但不是数据开发执行，也不是已复验关闭。
- 独立影响页 `datamaster-ui/src/views/meta/analyses/impact/index.vue` 仍引用示例data.js；资产详情 `LineageGraph` 已接真实配置血缘。不能把整个血缘功能称为假数据。

## 二、优先级与执行顺序

- **P0最高：空间功能流程配置与执行**。建立scope/准入结论契约、草稿发布配置及所有消费入口统一检查；未配置保留回退，已配置严格执行，不允许绕过。
- **P1第二：指标与数据分析增强**。围绕单数据源业务场景，按空间流程模式适配来源，改善常用计算与展示。
- **P2第三：质量整改闭环**。复用已有负责人、任务和结果，补人工可用性确认、处理关联、复验与关闭。
- **P3最后：其他问题**。真实影响分析、变化通知、SLA、契约演进、环境晋级、服务限流、标准审核、认证/产品运营和AI评测等完整保留，按项目需求逐步推进，不抢占前三项主线。
- 各主线自身必要的权限、数据安全、迁移及验证属于交付组成部分，不因其他问题排后就省略；运行验证仍须按用户明确授权执行。

状态：`已有`=核对到代码基础；`代码已改/未验收`=近期落盘但未通过实际运行；`待实施`=仅需求/评估；`按需`=不阻塞当前核心使用。
