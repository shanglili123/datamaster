# 第二批实施方案：已发布指标的受控查询与保存分析

## 1. 目标和交付边界

在指标定义与不可变发布快照基础上，打通「选择本体 → 选择指标及明确版本 → 维度/时间/分析过滤 → 查询结果 → 保存个人分析条件」。

本批只做单个指标、单个已发布 ADS 来源的聚合查询。前端提供结果表格，不新建图表编辑器，不接 DataEase，不改问数，不自动安装服务，不执行任何数据库迁移。

第一批发布仅代表登记元数据通过检查。本批执行重新验证空间、资产、字段、只读来源白名单与连接数据库，不把指标发布当作数据授权。

## 2. 业务规则

- 必须明确 metricId 和 version；禁止自动切换到最新版本。初次选择指标可以预选其最近版本，保存后保持原版本。
- 当前指标必须仍为 PUBLISHED；停用即禁止新的执行，即使旧版本快照存在。保存条件不代表永久获得执行权限。
- 本批只允许白名单绑定当前仍指向快照中的同一物理来源；绑定改指向后旧版本保留可读，但拒绝执行，需重新发布并审核来源，防止可变绑定ID继承旧审批。
- 聚合只使用所选不可变版本的字段映射、聚合方式和固定过滤，不从当前可变草稿回读计算定义。
- 本批支持 SUM、COUNT、COUNT_DISTINCT、AVG、MIN、MAX，COUNT 无度量属性时表示 COUNT(*)。
- 分组只能使用发布版本允许的维度，最多5个；分析过滤最多20条，仅允许发布维度与时间属性。
- 指标固定过滤不可删改，始终与分析过滤 AND 组合；不接收 SQL、表达式、表名、物理列名或自由排序。
- 有时间属性时必须提供完整时间范围，以源数据业务时间解释，使用半开区间 [startTime, endTime)，不做隐式时区转换或自动分桶。
- 本批不支持多指标组合、跨表、比率、快照余额、日去重合并月去重、查询结果再求和等自动聚合。调用方也不能把截断结果当作完整汇总。
- 返回默认100、最多500组；读取多一组检测截断。输出执行时间与耗时，执行时间不冒充源数据刷新时间。
- 明确「口径可追溯」不等于「历史数值可复现」：底层ADS补数或重建可能改变旧版本查询结果。

## 3. 安全前置与运行限制

### 3.1 默认关闭

执行开关默认false，未配置管理员批准的来源绑定ID和只读用户名白名单时拒绝执行。查询执行器不开启共享结果缓存、不主动归档结果或外发数据；接入Agent后，结果会进入工具消息并可能随流程、审计、会话记忆落库及发送至所配置模型服务，具体边界见数据分析Agent实施方案，不应宣称整条链路不存结果或不外发。

配置通过部署环境提供，不把凭据或实际生产授权名单写进代码库。只读用户名白名单只是显式运维声明，不是数据库GRANT证明；必须由运维实际撤销写权限并限制为已隔离的安全ADS视图。

### 3.2 执行顺序

1. 检查登录、执行权限、本体存在性与真实空间归属。
2. 读取当前指标状态和明确的已发布版本，并校验快照身份。
3. 从快照编译白名单SQL、参数和所用列集合。
4. 检查来源绑定白名单、当前数据源Doris类型及只读用户名白名单。
5. 连接配置数据库必须与快照数据库一致；不能借同名表跨数据库绕过资产权限。
6. 表治理必须开启且处于strict，解析结果必须命中正式数据资产并获准；关闭、warn、缺失、catalog降级全部拒绝。
7. 所有度量、分组、时间、固定过滤、分析过滤参与列均须授权；部分授权不可放行。COUNT(*)也须通过表级授权。
8. 敏感/脱敏参与列采取保守拒绝，不能认为聚合后天然安全。第一批只开放审批过的无敏感字段安全视图。
9. 通过上述检查后才能申请并发槽位并连接数据源；使用只读Connection、PreparedStatement、查询超时与返回行数上限。
10. 所有失败路径关闭连接、语句并释放并发槽位，返回不包含SQL、过滤值或连接凭据的业务错误。

执行期空间从本体数据库记录读取，不信任请求中的spaceId/spaceCode。当前仅做表/字段权限和安全ADS来源约束，不宣称实现通用动态行级权限；不同用户可见行范围不同的场景，必须事先通过视图/账号等可信数据层隔离，否则保持功能关闭。

### 3.3 查询构造

- 库、表、列名仅来自快照，仍作严格标识符校验和Doris引用。
- 条件值全部PreparedStatement绑定，类型按冻结属性定义转换；禁止拼接客户端字面量。
- IN限制元素数量，拒绝对象、嵌套数组、null和非法日期/数值。
- 大整数、小数条件可传字符串，避免浏览器Number精度损失。
- 所有维度分组并确定排序，不使用平台自由SQL接口，不返回内部SQL。

## 4. 保存分析

新增个人分析记录，保存：

- 本体ID；
- 后端确定的所有者ID；
- 名称、说明；
- 指标ID、明确版本、维度、时间范围、分析过滤、返回上限；
- revision及审计时间。

列表、详情、修改、删除只允许本人操作，并每次检查本体空间权限；管理员也不自动获得读取其他人的个人条件权限。不存数据结果、凭据或SQL。更新用revision防止覆盖其他窗口修改。

保存时验证指标版本和请求结构，但不连接Doris，不要求开启执行开关。实际执行时重新验证全部当前授权。升级到新指标版本需要用户明确选择，不自动迁移。

## 5. API与页面

- POST /ont/metric-analysis/query：执行受控查询，权限 ont:metric:execute。
- GET /ont/metric-analysis/page：本体内我的分析，权限 ont:analysis:list。
- GET /ont/metric-analysis/{id}：详情，权限 ont:analysis:query。
- POST /ont/metric-analysis：保存，权限 ont:analysis:add。
- PUT /ont/metric-analysis：更新，权限 ont:analysis:edit。
- DELETE /ont/metric-analysis/{id}：删除条件，权限 ont:analysis:remove。

入口：

- 数据探索 → 数据资产 → 指标分析。
- 本体工作台 → 指标分析。
- /ont/metric-analysis 为隐藏业务路由，复用当前空间本体选择。

页面按版本展示口径、单位、来源粒度与固定过滤；修改查询条件立即清除旧结果，过期异步请求不得覆盖新条件或新空间结果。明确显示结果是否截断，不提供未经权限设计的导出或分享功能。

## 6. 部署顺序

1. 第一批 sql/update_20261027_ontology_metric.sql 已人工审阅并完成迁移。
2. 第二批 sql/update_20261027_metric_analysis.sql 人工审阅后执行，默认不赋予普通角色权限。
3. 配置执行、列表、查看、保存等权限；同时需要既有指标列表/详情/历史版本读取权限。
4. 选择一个主题，先验证无敏感数据、权限范围明确的ADS视图；配置专用只读账号、资源限制和来源白名单。
5. 确认表治理strict及资产/字段登记完整，再在试点环境开启执行。
6. 完成本节验收后再讨论生产放量与DataEase接入。

本次开发不改application配置、不执行迁移、不访问实际Doris；配置键和示例见backend配套说明，以实际代码为准。

## 7. 验收矩阵

### 正确性

- 与基准SQL对比六种聚合、空数据、NULL值、COUNT(*)及COUNT(column)差异。
- 验证起始含/结束不含、日期非法、时间缺一端、时间字段与业务口径一致。
- 编辑草稿后旧版本执行仍遵循旧口径；变更来源映射再发布生成新版本，不篡改旧快照。
- 保存后重开保持版本、维度、过滤与时间范围，不自动执行。
- 结果超过limit时truncated=true；不把执行时间当作数据刷新时间。

### 安全与隔离

- 无执行权限、非空间成员、停用指标、伪造版本、跨本体请求均拒绝。
- 治理关闭/warn、无资产、catalog降级、部分字段授权、敏感字段、未批准来源、非只读名单账号、连接数据库不一致均拒绝且不连接外部库。
- 库/表/列中的SQL片段拒绝，过滤注入仅作为参数或被类型规则拒绝。
- 他人保存分析不可列出、查看、修改、删除；修改ownerId无效；旧revision更新失败。
- 切换空间/指标或修改条件后，旧请求结果不能显示在新上下文。

### 稳定性

- 超时/异常/并发上限场景不泄漏连接和槽位；错误响应不包含驱动连接信息。
- 只读账号不能写入；Doris端资源组和超时限制现场验证。
- 新增focused单测覆盖纯编译规则；集成环境验证权限、JDBC和数据库约束。本次不主动运行编译、测试、lint或迁移。

## 8. 后续方向

产品方向已调整为「本体驱动的指标语义层与数据分析Agent」，不再实施DataEase、iframe、BI Token或独立看板。当前受控查询和保存条件作为可复用的语义分析基础，Agent接入规则及上线前置见 [数据分析Agent实施方案](数据分析Agent实施方案.md)。
