# 指标查询来源页面配置（2026-11-16）

## 变更与边界

入口：本体工作台 → **查询来源配置**；指标管理工具栏和指标分析来源状态也可跳转。

- 按真实本体/概念表绑定批准和撤销来源，不再从部署配置读取绑定 ID 或全局用户名白名单。
- 账号取自现有数据源管理，页面只读展示，不在此保存密码或另建数据源凭据。
- 批准前必须明确确认数据库管理员已落实最小只读授权和必要的数据隔离，并填写说明。**该确认不是数据库权限验证**；系统不执行 GRANT 或连接测试。
- 独立管理权限与空间管理员身份共同约束；拥有执行或发布指标权限并不等于可以批准来源。平台管理员仍须是本体所属空间成员。
- 批准仅允许进入执行校验，不替代发布版本、空间成员、资产/字段治理、敏感列、元数据及 JDBC 只读检查。
- 当前状态和追加事件保存在应用数据库，不返回密码、原始连接配置或完整连接 URL；普通执行者的状态接口不返回账号和审批身份。

## 人工部署顺序

1. 备份并审阅 `sql/update_20261116_metric_source_approval.sql`，在应用 PostgreSQL 手工执行；**本次未执行迁移**。
2. 迁移添加两张批准/事件表，并为 `ont_concept_table`、`ast_datasource` 增加数据库维护的 `source_auth_revision` 和触发器。必须先迁移后部署新版 Java，旧程序正常更新来源也会推进该版本。
3. 审核后分配本体菜单下的专用权限：
   - `ont:metric-source:query`：查看配置和事件；
   - `ont:metric-source:approve`：确认、批准当前来源；
   - `ont:metric-source:revoke`：撤销批准。
   迁移不自动向角色授予权限；三种权限任一可读管理列表/历史，但写操作还需对应权限及空间管理员身份。
4. 在页面逐项确认真实数据源和绑定。旧名单**不自动导入为有效批准**，不能认为原有配置仍能放行。

## 部署配置

仅保留运行保护：

```yaml
ontology:
  metric-query:
    enabled: true
    timeout-seconds: 15
    max-concurrent: 4
```

- `enabled` 缺省由 false 改为 **true**，仅表示进入系统授权检查；空批准表仍拒绝所有来源。
- 显式配置 `enabled: false` 仍紧急关闭全部执行，页面不能覆盖。已有环境显式关闭的需由运维确认解除一次。
- `approved-binding-ids`、`allowlisted-readonly-usernames` 已退出运行时授权路径；保留旧配置也不会生效，更不会作为读取失败的兜底。
- 超时范围 1..60 秒；并发 1..16，按服务进程计算，集群保护仍由运维落实。

## 来源变化与撤销

绑定概念/数据源/库/schema/表/删除状态，以及数据源类型/地址/端口/连接配置/有效删除状态变化，将推进数据库授权版本。连接配置包括密码；密码轮换也保守失效。名称、描述、采集计数变化不影响批准。

来源 A→B→A 仍必须重新批准，不会因为恢复原值而自动恢复旧批准。批准和撤销使用 revision 和来源 token 拒绝旧页面覆盖；写入状态和追加事件同事务。撤销在来源失效时仍可操作，历史保留批准时的账号和表。

查询来源守卫使用主库当前批准，实际执行在创建外部连接前再次检查批准版本与来源版本。每个分页、每个对比/多指标实际执行都重新检查；不使用本地或 Redis 批准缓存。撤销阻止后续复核通过的执行，**不保证取消已发送给源库的查询，也不声称消除了所有检查与执行之间的竞态**。

## 接口

前缀 `/ont/metric-source-approval`：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/page?ontologyId=...&pageNum=1&pageSize=10` | 真实绑定与当前批准状态 |
| GET | `/settings?ontologyId=...` | 只读运行保护 |
| GET | `/history?ontologyId=...&bindingId=...` | 分页事件 |
| POST | `/approve` | `ontologyId,bindingId,revision,sourceToken,reason,readonlyConfirmed:true` |
| POST | `/revoke` | 同上，不要求 readonlyConfirmed |
| GET | `/status?ontologyId=...&bindingId=...` | 执行用户安全状态摘要，需 `ont:metric:execute` 和空间成员关系 |

管理读取为 query/approve/revoke 任一功能权限，且须为当前空间成员及管理员；所有归属由服务端重读，不信任客户端注入的空间、账号或数据源身份。
