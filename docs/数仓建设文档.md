# 数仓建设文档

数仓分层 → 表名前缀 ✅ 基本对

最常见的是 ods_ / dwd_ / dws_ / ads_ 前缀。
也有团队按层建库（ods 库、dwd 库……），表名里就不再写层前缀。两种做法都可以，库和层对应的情况反而比“库和域对应”多得多。

数据域 → 库 ❌ 一般不这么做

数据域写在表名的第二段：dwd_variety_approval_di 里的 variety 就是品种域。
不按域建库的原因：一个分析常常要跨域关联，按域建库会让权限和跨库 join 变得很麻烦，而且域的划分以后可能会调整，迁库的代价很大。
例外：少数超大公司会按业务板块（也就是业务分类那一级）拆库或拆项目空间，但这是按业务分类拆，不是按数据域拆。

主题域 → 表名 ⚠️ 只对了一半

主题域确实写在表名里，但只用于 ADS 层：ads_promotion_effect_region_1m 里的 promotion 是主题。
DWD/DWS 层的表名里写的是数据域，不是主题域。

正确的对应关系

```
              表名第一段      表名第二段           挂在表属性上
DWD/DWS 表：  分层前缀   _   数据域   _ 业务过程 …   + 业务分类
ADS 表：      分层前缀   _   主题域   _ 主题     …   + 业务分类
```

```
概念	落在哪里
数仓分层	表名前缀（或者对应库/schema）
数据域	公共层（DWD/DWS/DIM）表名的第二段
主题域	应用层（ADS）表名的第二段
业务分类	不进表名，作为元数据标签挂在资产目录上
```

所以在平台上建模型时，通常是先选层，然后根据层的不同选择数据域或主题域，再选业务过程，平台会自动拼出表名前缀并校验命名规范。业务分类则单独选一个树节点，作为归档用。

## 平台落地约定

- 本体层与数仓治理维度分开维护。本体层负责概念、属性、关系及其资产映射；数仓分层、业务分类、数据域、主题域负责物理表命名、资产目录和检索。
- 集成创建目标表时，数仓分层和表类型必选；明细/汇总/维度表选择数据域，应用表选择主题域，业务分类可选但会写入资产标签字段。
- `source_table`、`write_time` 等来源治理列属于目标表结构；质量检查、元数据探查和运行日志属于任务/元数据/质量模块，不写入数仓原表的治理分类字段。
- 物理表创建成功后必须同步登记 `AST_ASSET` 与资产字段，资产页面按分层、业务分类、数据域、主题域筛选；元数据目录仍以数据源/库/schema/表为技术浏览入口。
