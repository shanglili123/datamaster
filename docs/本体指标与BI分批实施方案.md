# 本体指标与 BI 数据探索：实施评估及分批交付

> 方向更新：不再建设传统 BI、DataEase 嵌入或独立看板产品。保留本方案中的指标语义、版本、维度和受控查询基础；后续以 [数据分析Agent实施方案](数据分析Agent实施方案.md) 为准。下文 BI 接入部分仅为历史备选，不在当前实施范围。

## 决策与边界

- 第一批复用本体的概念、表绑定、属性及属性字段映射，先建设指标定义、元数据校验和不可变发布版本；暂不新增平行数据集中心。
- 数据探索的「本体模型」流程和本体工作台均增加指标入口，不改变现有采集 / ETL / 问数执行链路。
- 第一批不执行指标 SQL，不连接外部 Doris 做校验，不安装 DataEase，不生成嵌入 Token，不修改运行环境配置，不执行数据库迁移。
- 元数据发布不等于通过数据质量、数据权限、刷新时效或结果一致性验证。界面和发布确认均提示此限制。

## 第一批验收清单

1. 当前空间选择本体、创建概念，绑定 Doris ADS 来源及概念属性物理列。
2. 新建指标草稿，填写稳定编码、名称及业务定义；不完整的来源、粒度或负责人可以暂存。
3. 校验 / 发布要求负责人、单位、粒度、聚合方式、Doris ADS 来源及有效属性映射完整。
4. 支持 SUM、COUNT、COUNT_DISTINCT、AVG、MIN、MAX；COUNT 未选择度量属性代表 COUNT(*)。
5. 维度和固定过滤仅引用当前概念、当前来源绑定中的属性；固定过滤采用结构化条件，不接受自由 SQL。
6. 发布后查看版本快照，确认包含来源表和字段映射；保存修改不覆盖已发布快照。
7. 使用旧 revision 修改或发布时应拒绝，提示重新读取，不能静默覆盖其他用户修改。
8. 停用保留历史，重新发布生成新版本；已发布指标不能删除，只有从未发布的草稿允许删除。
9. 普通用户不能访问非成员空间的指标；拒绝通过更换 ontologyId、conceptId、conceptTableId 绕过归属检查。
10. 本体 / 概念 / 表绑定存在指标引用时，在任何级联删除前拒绝操作。

## 发布前置

- 人工审阅并执行新增 PostgreSQL 指标迁移，先备份元数据库。SQL 文件不由应用自动执行。
- 新权限为 ont:metric:list/query/add/edit/remove/publish；由管理员向适当角色和空间分配。指标编辑选择项还依赖已有本体、概念、表绑定、属性、属性字段查询权限。
- 不默认给普通用户发布权限；前端可见性不能替代后端授权。
- 部署必须先完成迁移，再启用包含指标引用保护的新后端；缺少指标表时现有删除保护将失败关闭。
- 按 AGENTS.md，开发过程不主动运行构建、lint 或测试，验证由用户在本地执行。

## 后续批次

### 第二批：受控指标查询与保存分析

详细方案见 [指标受控查询与保存分析实施方案](指标受控查询与保存分析实施方案.md)。本批先支持单指标、明确发布版本和个人保存条件，执行默认关闭，不以 ADS 命名替代授权。

- 在第一批契约上登记受控数据集和字段角色，或由概念绑定提升为正式分析数据集，避免重复来源登记。
- 新建结构化指标查询入口，发布版本与权限范围在服务端解析；不能把现有自由 SQL 查询接口直接视为安全网关。
- 明确时间粒度、时区、刷新时间、可汇总范围；拒绝不兼容维度和错误聚合。
- 只读账号、表级 / 行列权限、查询超时、并发上限和权限感知缓存未就绪前，不对业务用户开放查询。
- 保存分析必须记录指标版本、维度、过滤和时间范围；不可仅绑定“最新指标”。

### 第三批：BI 适配与看板

- 独立 BI 适配模块处理外部资源映射、用户身份映射、看板发布校验及短时嵌入会话，本体不直接依赖 DataEase SDK。
- 社区版先验证 Doris 接入及指标结果；正式 iframe / DIV 鉴权嵌入需对目标版本和商业授权复核。公开分享链接不得作为敏感数据访问方案。
- DataEase 和问数使用不同的 Doris 只读账号，指向一致的受控 ADS 范围；BI 直连不自动继承平台脱敏和数据权限。
- 外部筛选参数不能充当租户隔离。复制链接、明细、钻取、导出、缓存都必须经过相同权限边界。
- 看板正式发布前登记指标版本引用并完成固定样例对账，不允许静默改变计算字段导致口径漂移。

### 第四批：问数统一

- 问数读取同一套指标定义、时间字段、固定过滤、维度和聚合约束，优先调用受控指标查询。
- 自由问数结果明确标记为探索性结果，不冒充正式发布指标。
- 同指标、同版本、同时间和过滤下，探索、看板、问数结果一致作为上线门槛。

## 仍需现场确认

- Doris 版本、实际 ADS 库 / 表 / 视图及只读账号授权（不在代码或文档中记录凭据）。
- DataEase 目标安装版本、授权、鉴权嵌入及行列权限能力。
- 空间与业务数据隔离方式，以及谁负责审批指标发布。
- 第一个试点业务对象和 5～10 个代表性指标；第一批仅支持单源原子聚合，不支持跨表、比率依赖、时间快照或自动去重汇总。
