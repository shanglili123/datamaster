# 原生模型结构化输出迁移记录

## 范围

除已完成的决策规划外，以下6条直接模型调用已改用LangChain4j AI Services具体POJO返回，不再自行剥代码块或截取首尾大括号：

1. AiSkillServiceImpl：报告模板生成。
2. AiSkillServiceImpl：表级Skill增强。
3. OntologyGenerateServiceImpl：本体模型生成。
4. OntologyGenerateServiceImpl：动作草稿生成。
5. AiActionDecisionServiceImpl：单动作选择/补参。
6. CollectorEtlTaskOpsServiceImpl：失败日志语义分析。

## 实现

- 共用`GovernedChatModelFactory`复用ActiveModelResolver、凭据兼容解密、URL规范化、超时/重试与GovernedChatLanguageModel，继续经过AiInvocationGateway统计供应商、模型、用量和并发准入。
- `StructuredModelService`的6个独立接口返回专用DTO；不引入自由JSON根对象，不启用未知供应方能力的严格JSON Schema。0.35框架类型化解析失败仍走各业务原有异常/人工处理/规则回退，不回退到字符串截取。
- ontology DTO/网关放ontology-interface，collector可选网关放collector-interface，AI负责实现。没有新增ontology-core或collector-core到AI实现的反向依赖。
- `IAiModelGatewayService.complete`/`IOntologyModelGateway.complete`保留文本兼容；本轮6条结构化业务链不再使用complete。
- 解析后的DTO在本体业务校验入口序列化成JSONObject是保留旧领域校验，不是从LLM文本提取JSON。
- 本体输出解析错误仍保留超过3张表缩到3张表重试一次，普通网络/服务错误不因此额外重试。
- 表增强仍过滤未知字段、限制文本/列表；报告校验required与章节绑定、数组要求、受支持章节，metricGrid的gridColumns显式映射回原Renderer的columns，表格columns为具体列列表。
- 单动作ID改为精确字符串，服务端严格转Long，保留候选校验、安全参数检查、0.80门槛、缺参人工处理及前置条件；NaN/Infinity不会放行。
- ETL模型分析改为可选网关；无AI/未配置/解析失败仍用规则诊断。保留原恢复策略，额外阻断HIGH风险和非暂态分类自动恢复，模型recoverable不是执行许可。

## 保留的JSON提取

`AiAskDataServiceImpl.extractJsonFragments/extractJsonFromReply`及问数页`extractJsonObjectsWithRange`为DB-GPT外部混合文本/报告/SQL展示协议适配，本轮明确保留；不将DB-GPT查询替换成直接模型调用。HTTP choices/content、SSE帧、数据库配置/业务参数的JSON解析也不属于模型输出截取。

## 配置与兼容边界

不升级LangChain4j0.35.0、Java8或模型供应商，不改环境配置，不新增数据库迁移。新的结构化调用由SDK处理网络重试；重试次数保持配置，`retryInterval`不再作为外层Sleep包裹结构化调用，避免双重重试，具体退避遵循SDK。纯文本旧网关保留原重试逻辑。

ETL调用使用持久化task空间传递调用上下文，支持该空间动态模型配置；不再单独读取collector中的模型API密钥。独立部署不含AI实现时退回规则，不自动通过HTTP调用其他AI服务。

报告模板保留动态数据schema的items/properties及style Map，但结构化POJO不保证语义正确或动态字段完整。供应方原生strict Schema需升级评估后单独启用，不能把当前POJO解析称为供应方强制保证。
