# 统一问数 Agent 与能力编排实施方案

初版确认：2026-11-17。2026-11-19 修订实现思路。

**状态：修订后的主要执行路径已接入源码，尚未编译或运行验收。** 本文优先于历史独立指标 Agent 和模式分流方案。实现边界见第 11 节。

## 1. 纠正的问题

此前按关键词将问题锁入指标Agent、普通DB-GPT、决策或报告分支，导致指标变成问答门槛；多次补提示词、业务关键词、默认日期及回退分支，没有解决统一执行机制。普通短问失败、引用历史数字冒充查询结果，说明整体未交付验收。

已存在的指标SQL、权限、报告、决策提案、审批执行服务是可复用能力，不等于统一问答已完成。历史精确参数场景的局部通过不能代表自然语言体验通过。

## 2. 产品目标

只保留一个用户面对的统一问数Agent，负责语义理解、任务规划、选择与组合能力、汇总证据及最终流式回答。不要求用户切换问答/决策/报告模式；前端模式选择应随执行机制统一而退出必选路径，旧API字段仅作兼容提示，不能继续锁定能力范围。

普通查询、分析、报告、决策和动作续接均使用同一可信会话/任务上下文。报告是一种输出能力，决策是一种分析能力，动作是一种具有副作用的执行能力，而不是三套割裂的聊天流程。

## 3. 执行机制（不是关键词分类或提示词补丁）

1. **校验上下文**：请求入口校验真实用户、空间、本体、数据源与会话归属；工具调用统一走权限和审计边界，资源访问仍由业务服务校验。
2. **模型自主规划**：框架驱动模型根据原问题、可用能力和已授权的会话引用，分别判断查询口径和交付目标。计划可以只有一步，也可随结果调整；不按业务关键词、模式或工具名分流，不为普通短问额外强制调用分类模型。
3. **执行并记录产物**：框架调用工具并返回结果。工具契约区分可直接展示的原生答复、可复用的查询证据、定义参考和结构化产物；同时标识失败、截断、过期和待确认。是否可用由产物类型与执行状态决定，不由工具名决定。
4. **检查目标并按需继续**：工具成功不等于任务完成。组合任务把原问题、验收条件和本轮产物对照；必要时让模型做结构化判断：已满足、还缺什么、是否需要用户补充。未满足时，框架在权限与预算内继续选工具；没有可行路径或预算耗尽时如实返回已有结果和缺项。模型只判断是否答到点，不替服务端证明 SQL 执行或业务动作成功。
5. **单步直答**：计划只要求普通回答、DB-GPT 正常返回可展示正文时，直接展示原生答复，不再用平台模型校验或改写；显式失败按失败展示。未取得执行凭证时，不标为平台已核验，不把答复文字、历史数字或模型自述当作查询证据。若还需要报告、分析或动作证据，按计划检查其他产物，不能仅凭一段正文结束。

移除独立指标问答Agent及其强制入口/子循环依赖。保留指标定义、版本、查询编译器、权限及工具，将它们接入统一能力目录。决策当前对指标子Agent的依赖也要解耦，不能只把普通入口改回DB-GPT就宣称完成。

## 4. 分开判断查数口径和交付目标

**查数口径与输出形式彼此独立。** 不按问句长短、所谓简单或复杂，也不按出现“报告”“决策”等字词决定查数路径。

| 用户需要的数据 | 选择依据 |
|---|---|
| 普通查数、明细、临时统计 | 默认把原问题和适用的已授权上下文交给 DB-GPT。不要求存在正式指标。 |
| 正式发布口径、指定版本或可复现的正式统计 | 平台指标工具按明确发布版本执行。DB-GPT 参考定义自行查出的值不能冒充该版本的结果。 |
| 后续步骤必须使用可核验数据 | 选择能提供相应执行证据的受控能力；涉及正式口径时使用平台正式指标。若无满足条件的来源，如实说明缺项。 |
| 用户要求沿用已有结果 | 先复核引用、访问权限、范围和时效；满足要求就复用，否则按原条件重新查，不抄聊天数字。 |

**指标、本体、Skill、元数据、资产都是按需参考，不是固定流水线。** 有适用且获授权的指标时，可将版本、业务定义、粒度、聚合和固定过滤连同原问题、适用 Skill 等一并提供给 DB-GPT；不塞入完整目录或其他来源的全局 Skill。指标不适用时直接继续普通问数，不要求用户选内部 ID 或批准“代理指标”。上下文不授予查询权限。

保留用户的统计对象、口径和时间范围。“统计销售记录条数”不默认“今天”；“统计上月销售记录条数”也不自动等于“按正式指标查”。只有可信上下文或业务配置有明确依据时才补参数；影响结论且无法解决的歧义再简短追问。禁止为示例问句写特判、预置日期或强制全量。

权限、来源批准、敏感字段或治理拒绝不等于能力不适用。不得切换工具来绕过；普通问答必须独立执行适用的数据访问约束。

## 5. 查数后的交付与会话续接

| 交付目标 | DB-GPT 普通查数 | 平台正式指标查数 |
|---|---|---|
| 直接回答 | 正常答复直接展示，不二次改写，不额外标为平台已核验。 | 按当前查询结果说明统计值、发布口径和实际范围。 |
| 报告 | 复用原生报告能力：可将查数与报告一次交给 DB-GPT；有适用模板按模板生成，没有则生成自定义报告。 | 将已取得的指标结果、发布版本和统计范围交给报告能力，不为换输出形式重查。 |
| 文字决策建议 | 可让 DB-GPT 查数后给出发现、建议和风险；没有正式指标也可以分析，不创建动作提案。 | 复用正式查询结果做比较、解释和建议，区分已查到的事实、推断和建议；不默认选动作。 |

一句话可要求多种交付。例如“按已发布口径查上月销量，再写简报和三条建议”：先执行一次正式指标查询，再复用结果写两种内容，不因“建议”触发动作。也支持先查后追问报告、决策后报告或执行结果报告，不要求换模式或重复输入条件。普通原生答复可供阅读，但未核验的文字不能当作平台查询证据或据此准备动作。

- 跨步骤引用服务端保存的查询/分析结果及条件、版本和执行时间；再次使用前校验用户/空间/任务归属和时效，需刷新时真实重查。
- 明确指定的可用报告模板按模板输出；未指定可匹配适用模板，无模板则自定义结构生成报告。
- 指定模板不可用应说明并提供自定义选项，不假装已使用模板，不把模板缺失当作整个分析不能继续。
- 报告不为填满模板编造数据；区分事实、推断、缺失项和未知，不把查询时间当数据刷新时间。

## 6. 决策与动作衔接

**文字建议不进入动作流程。** 只有用户明确要求选择现有动作、准备执行预览或提交时，才在取得可核验证据后进入相应步骤。选择候选、测算、影响预览、提交、查询状态和效果复查按目标组合，不要求每次全部执行；进入动作流程也不等于获准提交。

- 沿用可信上下文中的目标、对象、候选和参数，不让用户填内部ID。
- 有匹配的已配置动作/Workflow才准备执行；没有则给建议/人工步骤，不编造targetId或创建副作用以凑通过。
- 查询、选中方案、报告、自然语言路由不是写入授权。提交必须使用现有不可变预览、digest/revision、确认、审批、幂等及权限校验。
- 参数/对象/影响变化使旧确认失效；用户确认只能覆盖原明确范围。实际执行结果和效果观测必须查询，不能模型自报成功。
- 未测算收益/可行性保留未知，前后变化不是因果收益证明。

## 7. 流式展示协议

前端分开显示：

1. **灰色执行过程**：可折叠，流式公开活动摘要/工具事实，如检索来源、查询开始/结束、报告模板选择、待审批。不是原始思维链；不展示provider thought、原始提示词、SQL、凭据或敏感行。
2. **最终正文**：普通 DB-GPT 直答展示原生正文；需要综合多个产物时才根据证据生成统一正文。正文先给结论，再说明必要的口径、范围和限制；过程不得混进正文。
3. **结构化产物**：表格/图表/报告/提案/预览/执行状态单独事件引用，不能以文字声称代替产物。

建议统一事件：steps（活动状态/工具标识/安全摘要）、message（最终正文增量）、result（权威状态及产物引用）、report/decision等结构化产物、done、error。具体兼容方式实施前核对已有前端，避免同内容重复或迟到覆盖。

失败、待补充、取消不能全绿；不得提前标“已连接/已查询”。真实源库执行未知必须明确未知。

## 8. 成本、取消与安全

- 一个统一调用次数、token/时间、工具次数、返回规模预算，覆盖内部子调用；不能每个子能力另开无限额度。超预算保留真实进度及可续接任务，不自动重开。
- 路由及总结可多次模型调用，但有据复用结果，避免每步重复全文/重查/多余分类调用；费用与实际调用统计可核对，未知用量不当0。
- 取消阻止后续工具与迟到输出；不能谎称撤销已在途查询或已提交动作。
- 凭据服务端保管，日志有诊断编号、关联ID、安全错误分类及脱敏栈，不把异常原文发模型/前端。历史已有敏感日志须单独核对，不默认声明全平台安全。
- 不把安全约束做成繁琐业务确认，也不为体验删掉权限检查。

## 9. 修订后的实施顺序

1. 核对旧 DB-GPT 问答、文字建议和报告适配器。优先恢复普通问答的原生答复路径，保留权限与审计；有匹配上下文才提供，不新增硬编码直调分支。
2. 为工具声明产物类型和能力边界。由框架驱动模型规划和调用，统一判断单步直答、组合任务续跑及终止状态；不按 `ask_data` 等工具名决定完成，也不做固定的“查指标→查本体→问数”。
3. 让双查数路径都能接报告和文字建议；同会话复用合适结果。结构化证据与可展示正文分开；动作仍走现有预览、确认和审批。
4. 统一前端呈现：不要求切换模式；正文只展示一次，步骤、正文和结构化产物分开；明确显示实际范围、失败或待补充状态。
5. 补定向测试与验收说明；用户明确授权后再构建、启动和调用真实模型。旧构建或局部实测不作为本方案通过的依据。

## 10. 验收标准

不能只用精确指标ID/日期的长问题验收，至少覆盖：

- 普通短问可以一步交给 DB-GPT；有无适用指标或 Skill 都不阻塞。正常原生答复只展示一次，不触发平台二次校验或改写；远端明确失败不能显示成成功。
- 核对查询范围是否回答原问题：没有日期时不擅自加当天；只查某一天不能当作总量；未核验正文或历史数字不作为平台查询证据。组合任务缺少证据或产物时继续规划，不能仅因模型停止调用工具就报完成。
- 两条查数路径分别验证报告和文字建议；验证一句话组合输出、后续追问复用、指定模板/无模板/模板不可用。文字建议不应创建动作提案。
- 先查后决策、补参数、方案比较、动作预览、确认审批、状态/效果报告；没有动作不给假执行。
- 同一用户跨空间/本体/会话、撤权、过期证据、截断、工具失败、模型拒绝、断连、取消、预算限制、晚到结果。
- 当前开发页面真实操作，核对运行制品与源码版本，不能离线通过就宣称页面可用。

此前SQL计算/局部决策建议的测试证据保留；不扩大为报告、审批执行或统一自然语言链路已通过。1214停止收尾按用户要求不再测试。

## 11. 现有代码与修订方案的差距（2026-11-19）

修订后已移除按工具名直调的草稿。模型在 LangChain4j 工具循环中声明交付物，再选择工具；原生答复在适用的交付计划下直接展示，不经二次模型校验或改写。其他任务检查缺少的产物，必要时由模型核对口径和范围，并在共享预算内续跑。DB-GPT 问答、文字建议和单独的报告可带本轮选中的已授权定义；正式指标初查和续查共用原执行工具。DB-GPT 答复不能充当指标证据或动作依据。

仍未接通 DB-GPT 的可信查询执行凭证，不能在组合任务中把原生答复当作已核验数据复用。组合报告与建议当前可以使用正式查询证据；远端原生报告直出只用于仅需报告、且不要求正式证据的计划。以下构建和测试记录均为历史版本记录，不代表本轮修改已通过。

- 统一入口使用 LangChain4j `AiServices` 和动态 `ToolProvider`，不再运行独立指标 Agent。普通问答可以与指标、报告、决策在一轮组合；只有明确标记的未执行参数问题能让指标调用继续编排，执行失败或拒绝不能当作不匹配。没有本轮可用证据不生成数据结论，远端探索答复有独立的未核验提示。
- 保存的是可复查的单指标与两期比较条件，不是历史数据行。最近同会话查询和提案独立续接，复查最多选四项，按原条件和发布版本重新授权执行。资产与元数据只提供当前授权来源的指定表摘要，不读取业务行或历史行数。
- 可按已发布、来源匹配且有证据绑定的报告模板渲染；其他情况可生成自定义报告。明确指定但未使用的模板有独立提示，不能当成套版成功。历史模板若没有 `dataSchema.fields[].evidencePath`，仍不能通用绑定；绑定路径例如 `queries.0.data.rows.0.metric_value`。
- 决策可读取已保存预览、执行和效果状态；在提案卡片里进行显式测算、预览、确认及复查。聊天模型不自动准备或提交动作。普通问答结果的跨轮复用和远端执行证明尚未接通。
- SSE 的 `answer_delta` 是最终模型正文增量，`steps` 为服务端公开活动，`result` 才是权威结果。断流不按成功处理；`PARTIAL` 保留已完成产物，单次消息可同时展示查询表格、报告和提案。
- 使用 JDK 17.0.19 / Maven 3.9.11 运行 `mvn -B -pl datamaster-server -am package -Ddocker.build.skip=true -Ddocker.push.skip=true`：后端编译打包成功，671 项测试通过。首次测试发现普通聚合放开日期后影响时间分桶，已恢复分桶须提供起止时间，普通聚合仍可不提供。前端 65 项测试及 `npm run build:prod` 通过；临时预览的首页和编译后的入口脚本均返回 HTTP 200，预览已关闭。
- 上述验证轮次未启动后端、未调用真实模型。后续开发页面试用暴露了擅加日期、未核验数字被改写为结论等问题；这些试用不代表本次修订方案已经验收。
