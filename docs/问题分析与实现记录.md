## 2. 「检查下」深度静态检查结论

### 2.1 最大风险点验证(已实证验证,非猜测)
通过 `javap` 反编译 `spring-boot-autoconfigure-2.5.15.jar` (位于本地仓库 `D:\dev\repository`) 验证:

- **`Neo4jAutoConfiguration`**: 在 `spring.factories` 注册(L107), `determineServerUri` 在无 `spring.data.neo4j.uri` 时回退 `DEFAULT_SERVER_URI=bolt://localhost:7687`。但 `GraphDatabase.driver()` 创建 Driver **是惰性的,构造时不建连** → 开关关闭时不装 Neo4j 也能启动。

- **`Neo4jRepositoriesAutoConfiguration`**: 开关关时无 `Neo4jRepositoryConfigurationExtension` bean,条件通过后会激活,但 `@EnableNeo4jRepositories` 基包 = `AutoConfigurationPackages` = `com.datamaster.server` → **扫不到 `com.datamaster.neo4j.repository`** → 不会创建任何 repository bean,无害。

- **`Neo4jDataAutoConfiguration` 的 Neo4jTransactionManager**: 因项目已有 `AbstractTransactionManager`(jdbc `@Primary`)而 `@ConditionalOnMissingBean` 回退 → 不注册。

- 无 actuator 依赖，无 `Neo4jHealthIndicator`/`verifyConnectivity` 调用 → 无连接探活风险。

### 2.2 关键结论
开关关闭时,Boot 可能创建一个指向 localhost 的惰性 Driver bean(不连接、不失败),我方代码零 Neo4j 装配——比改动前(显式 `@EnableNeo4jRepositories` + `@EntityScan`)只少不多。

### 3.3 遇到的runtime错误及修正
- **错误**: `java.lang.RuntimeException: UPDATE 必须包含主键条件`
- **位置**: `ActionExecutionServiceImpl.buildUpdateSql` (L577)
- **原因**: 修改页未添加「条件字段」(至少 1 列且需在前端标记主键属性), 导致 `whereClause` 为空
- **对应操作**:
  - **新增**: 无需条件字段, 所有属性均可列入
  - **修改**: 必须添加 ≥1 列且标记 `primaryKey: true` (或业务主键), 否则抛出上述异常
  - **删除**: 必须添加 ≥1 列参与 WHERE (任意列), 无 `primaryKey` 强求; 若未添加应弹窗提醒

### 3.4 条件字段支持(已实现, 本次会话)
- **文件**:

- **后端改动**:
  1. `paramConfig` 新增 `condition`/`conditionLink`/`conditionNegate` 标记, `resolveConditionSpecs()` 解析为**有序**条件规格 `ConditionSpec`(semanticName + link + negate)

- **前端改动**:
  1. 动作配置弹窗新增黄色警告条: 动作类型为 UPDATE/DELETE 时提示「必须至少添加 1 个条件字段作为 WHERE 条件」

  3. `paramConfig` 保存/回显: 目标属性行(无 condition 标记) + 条件字段行(`condition:true` + `conditionLink` + `conditionNegate`) 合并为同一数组, 回显时按 condition 拆分为目标属性与条件行

### 3.7 执行记录「回退」功能(本次会话)
- **需求**: 「而且现在也没有回退啊」→ 动作执行要有基本留痕并可溯源回退
- **设计**: 在原执行记录上标记 `ROLLED_BACK` + 存 `rollbackSql`/`rollbackTime` 留痕; 回退按快照反向还原
  - `UPDATE` = 按 `BEFORE_DATA` 全列写回旧值(主键即执行条件)
  - `DELETE` = 按 `BEFORE_DATA` 重 `INSERT` 被删行

- **后端**: `IActionExecutionService.rollbackExecution(Long)` + `ActionExecutionServiceImpl`(L178-L231):

  - `dbQuery.getConnection()` + `setAutoCommit(false)` 事务执行, 失败整体 `rollback`; 成功置 `ROLLED_BACK` + 记录回退 SQL/时间
- **Controller**: `POST /ont/action/execution/rollback/{id}`(L110-112, 权限 `ont:action:edit`)
- **DB**: `sql/update_20260830_ont_action_execution_rollback.sql` — `ROLLBACK_SQL TEXT` + `ROLLBACK_TIME TIMESTAMP`(已在 PG 执行并验证列清单)
- **前端**: `api/ont/action.js` 新增 `rollbackExecution(id)`; `ActionPanel.vue` 操作列对 `EXECUTED` 记录显示「回退」按钮(L91, 橙色)+ `handleRollback` 确认流程(L875), `ROLLED_BACK` → 「已回退」紫色 tag(L431/L435)

### 3.10 回退「物理主键兜底」修复(本次会话)
- **运行时错误**: `表未配置主键属性，无法精确定位回退行`
- **根因(已实证)**: `buildRollbackSqls` 仅依赖概念属性 `isPrimary` 标记确定 pkCols; 测试概念「人物」的两个属性(`id=2091103263655919618` 年龄→列 age、`id=2093636152165736450` 标识→列 id)的 `is_primary` 均为 false → pkCols 为空直接抛错
- **修复方案**: 属性级主键缺失时, 用**物理表真实主键(colKey)兜底**:
  1. `buildRollbackSqls` 签名改为接收 `DbQuery dbQuery`(rollbackExecution 已提前 `getDbQuery` 再调用)
  2. 新增 `resolvePhysicalPkColumns(dbQuery, table, beforeRows, afterRows)`: 通过已打开连接的 `DatabaseMetaData.getPrimaryKeys(null, null, table)` 取物理主键列, 与快照行 keys 求交集(仅保留快照中确有数据的列)
  3. `getConnection()` 为 `dataSource.getConnection()`(Hikari/Simple 池), 每次独立连接 → 主键解析连接独立打开/关闭, 不影响后续回退事务连接
  4. 兜底后仍为空才报错, 报文更新为「表未配置主键属性且物理表主键无法识别」
- **验证**: 测试概念物理表 `user_1.id` 是真实主键(colKey=true), 快照行含 `id` → 交集命中 `id`, 回退 UPDATE/DELETE 可精确定位
